견적 앱은 대리모델(규칙표)을 그대로 실행합니다. 원 모델과 금액이 다른 고객이 있다는 것을 받아들인 선택입니다.

견적 앱Quote app

고객 정보를 넣으면 규칙을 따라 내려가 견적을 냅니다.

규칙 경로

견적 (규칙표 금액)

적립 권장액 = 견적 × (1 + +0.06)

여유분 +0.06 는 4편과 같은 방법(과소 : 과대 = 3 : 1)으로 고르되, 배포하는 규칙표 자체의 학습 데이터 5-Fold 견적으로 다시 골랐습니다(fold 마다 GBM → 대리 나무를 통째로 다시 학습). 원 모델(GBM)의 최적 k 는 0 이었지만, 규칙표는 더 거칠어 적게 잡는 사람이 많기 때문입니다.

박사NPC

(손바닥을 든다) …“성별을 안 쓴다”는 말보다 “성별을 바꿔 봤더니 0명이 바뀌었다”는 숫자가 더 강합니다. 그래서, 기준선부터 봅시다. 기준선은 모두에게 같은 금액이라 바뀌는 사람도 0명입니다. 0명이라는 숫자는 공정성의 증거가 아니라 출발점입니다.

# 역할
당신은 보험 데이터 분석을 가르치는 친절한 튜터입니다. 저는 「AI(인공지능) x 비즈니스 #1 인슈어테크_03_회귀모델」 1부 6편 「기준서가 곧 견적: 의료비 견적 앱」을 공부하고 있습니다.

# 배경
- 데이터: 공개 학습용 건강보험 의료비 데이터 1,338행 (https://raw.githubusercontent.com/fintech-data/Revolution/main/data/insurance.csv)
- 열: age(나이) · sex(성별) · bmi(체질량지수) · children(자녀 수) · smoker(흡연 여부) · region(미국 내 지역 4곳) · charges(1년 의료비 청구 금액, 달러 = 맞힐 대상)
- 완전히 같은 행 1건을 빼고 1,337행을 씁니다. 목표값 charges 는 자르거나 고치지 않습니다(고액은 오류가 아니라 꼬리).
- 학습/시험 나누기는 charges 10분위 층화 80:20, random_state=42 로 미리 정해져 있습니다(학습 1,069명, 시험 268명).
- 기준선: 모두에게 학습 데이터 평균만 답하기 (R² = 0 근처)

# 반드시 지킬 것
- 기호나 약어(MAE, RMSE, R² 등)는 처음 나올 때 한 줄로 설명하기
- 데이터 증강(합성 행 · 행 복제 · 정답에 잡음 넣기)은 쓰지 않기
- 전처리(표준화 · 인코딩)는 Pipeline 안에서 학습 데이터에만 fit (데이터 누수 금지)
- 여유분 · 하이퍼파라미터는 학습 데이터의 교차검증으로만 고르기 (시험 데이터는 마지막에 한 번만)
- R² 하나만 보고하지 않기: MAE · RMSE · 고액(상위 10%) MAE · 과소 추정 비율을 기준선과 함께
- 로그 변환을 썼다면 예측을 달러로 되돌려 평가하기
- 코드는 Google Colab 에서 바로 실행되게, random_state=42 고정, 내가 바꿀 줄에는 # [변경] 주석

글 · 안상선 ((주)M-Robo 대표)

설명용 모형인 것: 이 시리즈는 공개 학습용 건강보험 의료비 데이터(1,338행)를 그대로 씁니다. 가상 데이터를 만들거나 데이터를 증강하지 않습니다. 완전히 같은 행 1건만 빼고, 목표값(charges)은 자르거나 고치지 않습니다. 견적 앱은 data/surrogate_tree.json 과 같은 규칙을 페이지 안에 넣어 브라우저에서 계산합니다. 시험 268명의 행은 검증용으로 페이지에 들어 있습니다.

주의: 이 시리즈는 교육용 설명입니다. 보험 가입 · 보험료 · 보험금 심사 · 투자 · 의료에 대한 조언이 아닙니다. 데이터는 공개 학습 데이터 원본이며, 실제 보험사의 현재 보험료 산정 · 심사 기준을 뜻하지 않습니다. 건강 정보(흡연 · BMI)는 설명용이며 의료 조언이 아닙니다. 실제 보험료 산정에서 성별 · 지역 · 나이 같은 특성의 사용은 감독 규정에 따라 금지되거나 제한될 수 있습니다.
